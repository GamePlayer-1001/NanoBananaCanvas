## 一、文档定位

这份清单不是历史年鉴，而是当前项目的**执行导航**。

它要解决的是：

1. 现在项目已经做到哪里了
2. 当前主链还剩什么
3. 接下来优先推进什么

已经完成且不会直接指导下一步开发的大段历史过程，应该留在 `archive` 或 git 记录里，而不是继续堆在主清单里污染判断。

---

## 二、当前阶段判断

### 2.1 总体状态

当前项目已经不是 MVP，也不是单纯的平台化升级早期，而是进入了：

**`P1 收口完成 + P2 大部分现实落地 + 进入“运行时稳定化与兼容性治理”阶段`**

### 2.2 当前真实现状

已经成为运行时现实的主链包括：

1. 工作流画布编辑
2. 工作区 / 文件夹 / Explore / Workflows
3. Clerk 登录桥接与账户资源归属
4. Stripe 支付、账单、积分、账本与 Portal
5. 图片 / 视频 / 音频异步任务
6. Cloudflare Workflow / legacy queue 双轨编排
7. Agent 工作流共创、诊断、优化、审计与回放

因此当前最重要的问题，已经不再是“有没有这些能力”，而是：

1. 文档是否与现实一致
2. 主链是否还有未收口的人工作业
3. 后续迭代是否会因为旧设计误导而引入不兼容

## 四、当前主链

### 4.1 产品主链

当前真正的产品主链是：

1. 用户进入 Landing 或公开页
2. 登录后进入 Workspace / Canvas / Billing / Account
3. 使用画布搭建工作流
4. 同步或异步执行模型节点
5. 生成资产、保存结果、发布到公开空间
6. 通过 Agent 辅助搭建、修改、解释和诊断工作流

### 4.2 技术主链

当前真正的技术主链是：

1. `use-flow-store` 维护工作流真相源
2. `use-auto-save` 和 workflow API 做持久化
3. `lib/tasks/service.ts` 编排异步任务
4. `apps/worker` 做长任务后台协作
5. `lib/billing/*` 做账本与扣费闭环
6. `lib/agent/*` 做画布摘要、计划、落图与审计

### 4.3 文档主链

当前文档主链应当收口为：

1. `项目框架结构.md`
2. `项目规划清单.md`
3. `项目执行规范.md`
4. `多模态架构设计.md`

archive 中的重要专项文档继续保留参考价值，但不应再作为默认主入口。

1. git 历史
2. `archive`

## 八、当前优先级

### P0

1. 修正文档与代码现实不一致的问题
2. 保持主链测试、构建、部署链不回归
3. 完成生产手测闭环

### P1

1. 继续补文档镜像与模块 `CLAUDE.md`
2. 补关键边界测试
3. 清理历史兼容债务

### P2

1. 在主链稳定前，不急着继续扩新大功能
2. 只有当真相源已经明确，才继续做更深层 Agent / 任务 / 运营扩展

---

## 九、执行原则

从现在开始，这份清单的维护必须遵守三个原则：

1. 只保留当前仍指导行动的信息
2. 已完成历史过程不在主清单里无限堆积
3. 一旦代码现实改变，先修正文档口径，再推进新开发

---

## 十、结论

当前项目最需要的不是继续膨胀规划，而是：

1. 把已经落地的主链写成稳定真相源
2. 把真正未闭环的生产事项留在台面上
3. 避免后续继续按过时文档做开发，制造新的不兼容

这才是现在这份规划清单的价值。
