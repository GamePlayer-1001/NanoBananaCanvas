# Geo SEO 实施手册

用于需要处理国家、区域、城市、服务区域等地理意图的 SEO 任务。本文档关注的不是多语言翻译，而是“不同地理目标市场应如何被搜索引擎理解和匹配”。

## 使用场景

- 网站要覆盖多个国家、州、省、市或服务区域
- 需要设计城市页、区域页、门店页、服务地区页
- 需要判断 geo landing page 是否会被视为 doorway pages
- 需要规划地域化内容、内部链接和本地信号

## 先判断目标层级

在给方案前，先确认用户真正需要哪一级 geo targeting：

| 层级 | 典型场景 | 常见页面形态 |
| --- | --- | --- |
| 国家级 | 不同国家的市场进入 | `/us/`、`/uk/`、`/sg/` |
| 区域级 | 省州或大区业务覆盖 | `/california/`、`/guangdong/` |
| 城市级 | 城市搜索意图强 | `/new-york/seo-agency/` |
| 服务区域 | 无实体门店但提供本地服务 | `/service-areas/seattle/` |

不要一上来就大量铺城市页。先看业务是否真的有地域差异、供给能力和用户意图支撑。

## Geo SEO 与多语言 SEO 的区别

- 多语言 SEO 解决“说什么语言”
- Geo SEO 解决“服务哪个地点”
- 两者可能叠加，但不要混为一谈

例子：

- `/en-us/` 与 `/en-gb/` 是语言 + 地域的组合
- `/shanghai/office-rental/` 是纯地域目标页

## URL 与信息架构

推荐让地域维度在 URL 和站内结构中可见：

- 国家级：`/us/`、`/jp/`
- 城市级：`/locations/chengdu/`
- 服务区域：`/service-areas/austin/`

原则：

- 用稳定、可扩展的目录规则
- 不要让相同服务在多个路径里互相竞争
- 让上级聚合页能串联下级地域页

建议的层级：

1. 国家 / 区域总览页
2. 城市 / 服务区域页
3. 门店 / 办公室 / 实体位置详情页

## 地域页必须具备的独特价值

合格的 geo landing page 不应该只是把城市名批量替换进去。至少要有这些真实差异：

- 当地服务范围或交付方式
- 当地案例、评价或客户类型
- 当地价格、时区、配送、法规、联系方式
- 当地 FAQ
- 与该区域相关的实体地址、电话、营业信息

如果页面只有城市名不同、正文几乎相同，就要警惕 doorway 风险。

## Doorway 风险识别

高风险信号：

- 数十个城市页文案几乎一模一样
- 所有页都导向同一个表单，没有真实地区差异
- 没有本地证明材料，只有关键词替换
- 用户从页面中无法获得本地化信息，只是为了吃词

降风险做法：

- 合并无差异的页面到更高层级聚合页
- 只为高价值地区建立独立页
- 给每个地域页加入独特内容块
- 建立清晰的区域导航与上下级内链

## 本地与地域信号

可用信号包括：

- `LocalBusiness` 或相关 schema
- NAP 一致性：名称、地址、电话
- 门店页 / 办公地点页
- 地区化 FAQ
- 本地客户评价、案例、图库
- Google Business Profile 等外部本地资料

如果是纯服务区域、没有公开门店：

- 不要伪造地址
- 强调服务范围、响应时效、支持方式
- 用案例、团队能力、服务流程建立可信度

## 页面级优化

每个 geo 页至少检查：

- Title 是否包含核心服务 + 地域修饰词
- H1 是否与页面主题一致
- Meta description 是否说明该地区的具体价值
- URL 是否简洁稳定
- 正文首屏是否明确服务对象和区域
- 页面中是否有独特本地内容块
- 是否有指向上级区域页和兄弟页的合理内链

## Schema 与地图信息

常见可用类型：

- `LocalBusiness`
- `Organization`
- `FAQPage`
- `BreadcrumbList`

规则：

- 只标记真实存在且页面可见的信息
- 没有实体位置时不要伪造 `LocalBusiness` 地址
- 多门店时，优先门店详情页承载最具体的本地实体信息

## 内链与聚合策略

推荐结构：

- 首页或服务页链接到区域总览页
- 区域总览页链接到重点城市页
- 城市页回链到上级区域页和相关服务页

避免：

- 所有城市页孤立存在
- 只有 XML sitemap，没有站内可抓取导航
- 同一服务 + 地域存在多个重复入口

## 验证方式

重点检查：

- 地域页是否被收录
- 地域 query 是否落到正确页面
- 页面之间是否出现关键词蚕食
- 非目标页是否抢占目标地域词

工具：

- Search Console 按页面 / 查询 / 国家过滤
- Screaming Frog 查重标题与正文相似度
- 日志与 GA4 观察地区流量与转化

## 输出模板

### 现象

- 哪类 geo query 没有落到预期页面

### 本质

- 地域意图没被页面结构承接 / 页面过于模板化 / 地域信号不足

### 修复

- `P0` 先合并重复页或修正信息架构
- `P1` 补真实本地内容和 schema
- `P2` 扩张高价值地区并建立聚合层
